# 播放与字幕配置

入口：设置中的偏好页面 → 播放与字幕。只影响当前浏览器，不修改角色人设或主工作区布局。

配置由 `shared/preferences/playbackConfig.ts` 管理，包含默认值、类型、范围校验、版本化存储键及读取/保存入口。新增参数应先在此声明和归一化，再接入设置界面与实际消费者，避免重复硬编码。

| 参数 | 范围/默认 | 消费者 |
| --- | --- | --- |
| captionChars | 16–40，默认40 | 独立直播画面，每页固定最多两行 |
| captionLead | 0–0.15，默认0.035 | 音频进度到字幕页的估算映射 |
| fallbackMsPerChar | 100–500，默认220 | 无音频进度时的字幕估时；当前仅开发配置 |
| bookSegmentChars | 60–240，默认120 | 下一书籍chunk的语音分组 |
| prefetch | 默认开启 | 播放当前句组时预生成下一组 |

主页面通过BroadcastChannel同步归一化配置到独立直播窗口。切换分段设置不取消当前段，下一chunk使用新参数；预生成可能产生未播放音频的费用。

字幕仍按音频进度估算，不具备词级时间戳。后续引入供应商时间戳时，应新增时间轴适配器，优先使用真实时间戳、缺失时再使用当前估算。不要将提前百分比宣称为精准对齐。

语音任务现在拥有递增taskId，phase和outcome区分准备/播放与完成/取消/失败；speechClock输出同一任务的音频秒数、时长或系统语音charIndex，直播窗口按taskId重置分页，重复文本也视为新任务。系统语音支持onboundary时优先使用实际文字边界，无支持时保留估算。

captionTimeline.ts提供时间cue查询与字符位置分页的纯函数。当前TTS接口只返回音频Blob，尚未向模型音频接入供应商词级时间戳；timedCaption为后续适配入口，不能宣称当前已精准对齐。现有performance开始/结束回调仍关联语音生命周期，尚未重构所有音乐/身体操作为统一任务。

测试覆盖100段连续模拟播放、重复文本新任务、取消后旧边界失效、重复完成只回调一次、80字后续20字分页。此为模拟状态回归，不等价于真实一小时音频/后台窗口验收。

验证：前端构建；`node --test tests/*.test.mjs`。人工需验证字幕设置同步、预生成关闭、朗读中取消、切换角色、刷新和持续朗读。
