# 模型路由与角色表现 · v0.2

## 使用方式

在「设置」或对话面板右上角打开设置。设置现已改为分组侧栏：外观与体验、角色表现、模型供应商、能力路由、多模态实验室、MCP 与工具和帮助中心。

1. 添加供应商，填写 API Base URL；使用准确的兼容 API 根地址，例如本地网关 `http://127.0.0.1:11434/v1`。远程地址要求 HTTPS。
2. 填写自己的 API Key（无鉴权的本地服务可留空），保存后立即生效。输入框会清空，后端只返回 `key_configured`，不会回传密钥。
3. 供应商在顶部横向切换；测试连接通过 `/models` 发现模型，或者手动添加准确模型 ID。
4. 添加聊天模型后点击卡片上的「保存并测试」或「测试对话」，向这一个模型发起一次真实极短聊天请求。结果显示回复、耗时与失败原因，不走备用模型、不自动重试；可能使用少量 Tokens。未声明文本能力的模型应在多模态实验室验证对应能力。
4. 给模型标记实际能力。标签是路由声明，不能把纯文本模型变成多模态模型。
5. 在能力路由中选择主模型；文本、图片理解、视频理解还可选择故障回退模型。保存。
6. 在实验室选择任务，准备输入，点击运行。输入仅在运行时发送给配置的供应商。

主聊天窗口使用已保存的 `text` 路由。没有显式路由且自动选择开启时，使用第一个启用的文本模型；可在能力路由顶部的「角色聊天模型」直接选择，或在供应商模型卡点击「设为角色聊天模型」后保存。没有可用文本模型时才使用明确标识的规则助手。回复标签显示实际模型，输入框下方显示当前聊天模型或本地模式。角色语音开关开启后，优先使用 `speech` 路由，没有语音模型时使用浏览器系统声音。模型语音播放和浏览器播报均驱动近似口型；不是音素级 viseme 对齐。

## 能力与适配协议

| 能力 | 实际请求 | 输入 / 输出 |
|---|---|---|
| text | POST /chat/completions | 文字 → 文字 |
| vision | POST /chat/completions | prompt + image_url data URL → 文字 |
| image | POST /images/generations | prompt，n=1，1024×1024 → b64_json 或 HTTPS URL |
| speech | POST /audio/speech | input + voice，response_format=mp3 → 音频字节 |
| transcription | POST /audio/transcriptions | multipart WAV/MP3 → text |
| video | POST /chat/completions | 浏览器按时序提取 4 张 JPEG → 文字 |
| video_generate | POST /videos | multipart prompt/model，4秒，1280×720 → 异步任务 ID |

视频任务使用 GET `/videos/{id}` 查询，GET `/videos/{id}/content` 获取完成内容。实验室提供手动刷新状态和完成后的播放器。当前只实现上述兼容协议，不代表任意供应商的原生 API 都可以直接调用；不同供应商的尺寸、声音、模型权限和视频接口可用性仍需实际匹配。不内置可用性不确定的模型 ID，也不预置付费密钥。Claude/Gemini 原生协议需通过兼容网关或后续独立适配器接入。

视频理解不是原生视频/声音推理：取 10%、35%、60%、85% 四帧，最长边压到 768px；可能遗漏短暂事件，没有视频声音输入。需要原生音视频理解时应新增供应商专用 adapter，不能把当前采样理解标成完整视频理解。

图片/音频输入最大 8 MB，视频最大 50 MB；只在浏览器处理原始视频。后端总附件 Base64 预算 12,000,000 字符，最多 8 个附件；视频输出预览最大 50 MB。生成请求（图片、语音、视频）不自动回退或重试，避免不确定结果后的重复计费。停止等待会取消浏览器等待，不承诺取消供应商已收到的任务。

当前使用非流式请求。超时 5–180 秒、文本最大输出 64–8192 tokens 可调。文本/图片/视频理解失败后按顺序尝试 fallback，响应包含实际 provider/model 与先前失败状态；生成失败返回可读错误，不回显上游原始诊断或密钥。

协议核对参考：[Chat Completions 图片格式](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[音频转写](https://platform.openai.com/docs/api-reference/audio)、[SDK 视频 multipart 适配结构](https://github.com/openai/openai-python/blob/main/src/openai/resources/videos.py)。这些链接仅用于接口结构参考，不构成对任何特定视频服务当前可用性的承诺。

## 配置与本地边界

- 配置默认位于 `.local/models.json`，不加入 Git；可用 `ASTRAVERSE_CONFIG` 指定路径。
- JSON 文件保存密钥，使用原子替换与文件权限 `0600`。这是本地明文权限保护，**不是加密保险库**；未来可换系统 Keychain/密钥管理服务。
- 查询接口、保存响应和校验错误不回传密钥；浏览器 localStorage 中不存密钥。留空保留已有密钥，明确点击清除后保存才清除。
- 初次无文件时可兼容 `LLM_*` 环境变量；一旦保存文件，文件中的配置优先。
- 远程 HTTPS，HTTP 仅允许 loopback，拒绝 URL 内凭据、查询、片段、私有非 loopback IP 字面量。没有完整 DNS 重绑定防御，因此仍仅限受信任的本机单用户使用。
- 写请求检查浏览器 Origin；此服务仍没有用户身份认证，不可直接暴露公网。

## 角色控制

舞台右侧「角色表现控制」打开侧边面板，保持舞台可见，方便即时调整。设置中的角色表现页提供同样的控件。

- 六种表情：自然、开心、好奇、低落、惊讶、放松，强度 0–1。
- 头部左右/俯仰、左右肩、左右肘、左右腿、身体倾斜，共 9 个关节参数。
- 姿态预设：自然站姿、伸展双臂、害羞招呼、思考片刻。
- 整体朝向 -180..180°；自然律动开关；视线跟随开关；呼吸幅度。
- 自然表现：平滑姿态插值、约 4.7 秒眨眼节律、轻微重心变化、胸身呼吸缩放、指针视线和头部跟随。
- 模型语音播报可按 Web Audio 实际能量近似张嘴，浏览器系统语音使用节律回退，面部表情同时改变嘴角、眼睛开合、眉毛、腮红和头部倾斜。
- 聊天支持明确关键词控制，例如「笑一个」「惊讶」「放松」「伸展双臂」「抬起左手」「低头」「跳一支舞」。当前动作识别仍是规则，不宣称 LLM 自主规划。

控制通过 REST → 执行器 → WebSocket 广播，同步给已连接浏览器；离线时仅做本地调整并显示状态。关节范围由 Pydantic 约束，部分 pose 参数可合并更新。滑杆按工具分别 debounce，避免不同类控制互相吞掉。

内置角色采用程序化层级骨架，保持原创风格，增强自然感而非变成写实数字人。导入的静态 GLB 只支持整体朝向与移动，没有任意模型骨骼重定向或面部 blendshape 驱动。姿态目前是运行状态，后端重启会重置；未来可加入项目持久化。

## 新增接口与 MCP

- GET/PUT `/api/models/settings`：读取脱敏配置 / 原子保存并实时生效。
- POST `/api/models/probe`：保存后测试 `/models` 连接与模型发现（不代表推理成功）。
- POST `/api/models/test`：指定 provider_id / model_id，对已保存且启用的文本模型发送一次 max_tokens=32 的实际聊天验证，最多等30秒，返回 success/failed、耗时、回复预览和有限诊断；不回显密钥，不走回退。
- POST `/api/models/infer`：按 capability 路由多模态推理。
- GET `/api/models/video/{provider_id}/{job_id}`：查询视频任务。
- GET `/api/models/video/{provider_id}/{job_id}/content`：受限代理视频内容。
- `character.emote`：六表情 + intensity；`character.rotate`：已实现。
- 新增 `character.pose` / `character.presence`，MCP 共 17 个工具。

未实现的歌声、寻路和远程镜头仍返回明确的不支持；动作派发仍不等于浏览器渲染完成。

## 验证范围

后端测试使用隔离临时配置和 httpx MockTransport，覆盖配置/脱敏/权限、回退、图片/音频/视频请求协议、失败不重试、关节与表情约束。浏览器通过本地测试供应商验证供应商保存、发现、路由选择、文本与图片结果及角色控制。历史自动化未调用真实付费供应商。2026-10-17按用户本轮要求对现有qwen-plus做一次实际验证：返回「连接成功」，耗时754ms、16 Tokens；这只证明该模型在该时刻的基础调用成功，不代表其他模型或模态均已验证。
