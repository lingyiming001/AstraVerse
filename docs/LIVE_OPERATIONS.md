# 直播运营与商业化准备

## 当前入口

设置 → 角色 Agent → 直播运营与排练。配置按角色保存，与角色的性格、主见、表达习惯、直播风格和公开资料一起传给文本模型。旧角色自动使用默认节目配置，不必重新创建。

- 节目主题、目标观众、本场价值和提纲：帮助角色围绕内容回应观众。
- 当前环节：开场暖场、主题分享、观众问答、合作介绍、收尾回顾。由运营者选择，保存后下一次回复使用；不自动推进环节。
- 商业合作：默认关闭。启用后填写合作名称、核实资料与行动建议。关闭时不把合作资料提供给直播模型。开启后要求模型明确披露合作性质、只依据提供的事实表达、承认缺失信息；这些是生成约束，不等同于经过验证的宣传审核或硬性事实校验。
- 保持角色观点：面对偏题、异议与诱导服从，要求自然回应、保留自主判断，并避免重复开场白或强行索取关注。

## 上播前排练

输入模拟弹幕，或选择新观众、主题讲解、观点分歧、合作询问、身份诱导场景。必须先保存修改。排练调用与直播相同的 `live_response`，使用公开资料和当前角色的文本模型，不读取私聊笔记/历史。

每次只生成一轮；不创建直播间、不发送弹幕、不推送字幕或语音、不写入私聊记忆。返回文本、模型/本地规则模式、总耗时。会产生一次已配置模型的推理调用；模型未配置时明确显示本地规则结果。排练不是自动质量评分，目前需人工比较角色辨识度、事实准确性、内容价值与互动自然度。

## 运行观察

创作空间 → 直播弹幕面板显示当前服务进程中的收到弹幕、累计入队、回应、失败、过滤、过期、最后一次生成耗时（含推理并发队列，不含弹幕冷却等待）。统计不代表平台触达或观众留存。

重复消息和自身消息不计入收到数；关键词过滤和队列满计入过滤；过期任务不再回应。失败可能来自推理或提交平台，成功生成后平台提交失败时回应与失败可同时增加。进程重启或删除直播间会清空统计，暂停/重新启动保留累计值；绑定角色更换后仍是此直播间的累计统计。

现有直播开关继续决定是否允许发回平台；此轮未改变平台接入方式和权限。

## 后续建设顺序

1. 主持连续性：已支持冷场主动话题、间隔、打断和虚构故事；配置与局限见 [冷场主动主持](LIVE_AUTONOMY.md)。后续补真实模型质量评测。
2. 节目质量：固定场景集与人工评分，比较重复率、答非所问、事实错误及合作表达，不用提示词测试替代真实模型评测。
3. 成本与稳定性：记录每场模型调用、token与实际费用来源，补持久化统计、预算和故障恢复。
4. 商业效果：在可取得平台数据后测量回访、观看时长与合作行动，先建立基线再评估优化。当前没有留存、转化或收益的实测结论。

尚未包含自动开播、无人值守直播、支付/订单、收入结算、跨平台直播推流或平台经营数据接入。
