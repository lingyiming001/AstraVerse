# 角色 Agent 协作

入口：角色设置 → 更多设置 → 能力与自动行为 → 自动动作、选歌与弹幕管理。每个角色分别保存；旧角色默认不启用新增协作者，已有对话、动作与直播行为继续有效。

## 分工

- 对话 Agent：现有角色模型，负责唯一一份台词、角色观点与动作意愿。仍拥有独立角色记忆；资源与场景请求走既有权限和能力检查。
- 动作 Agent：启用后用于普通模型聊天和直播。默认本地协作，复用对话给出的表情并约束明显情绪冲突，不额外请求模型。模型导演模式另发一次受限JSON判断，使用该角色当前文本模型配置；只接收当前台词、消息、性格和已授权身体动作，不读取长期记忆或工具凭据。可调整表情/手势/强度，或取消已提出的身体动作，不能提出新的动作、改台词、控制场景资源或绕过模型能力限制。
- 弹幕管理：本地规则协作者，按角色配置，分别在每个直播间维护有限去重窗口。处理基础辱骂、统一空白/标点后的重复内容和同昵称发言频率；通过后才进入现有关键词筛选、队列、对话和输出审核。被过滤消息只发通用管理事件，不回显原文、不进入对话历史、不重置冷场次数或打断主动生成。

这不是多角色同时争抢话筒，也没有新增多个用户可见的对话线程。执行仍由统一出口负责；身体/资源能力与动作意愿继续受既有检查限制。直播当前只发送表情手势，不接受后台动作导演新增未获授权的全身动作。前端只驱动当前选中角色。

## 成本与失败处理

模型导演启用时，每轮普通模型对话或直播生成后多一次模型调用，最多等待8秒；失败、格式错误或越权动作回退到原有表现，再应用本地情绪约束。它不拥有工具执行权。会增加响应延迟和模型费用，全天直播的主动次数上限不代表模型调用或token预算。排练也可能调用动作导演。无可用模型时不为本地规则回复调用模型导演。

对话结果包含team.motion状态（disabled/local/llm/fallback），直播事件也携带此状态，方便后续诊断。插件/工具的早返回路径继续使用原处理器，不额外经过模型导演。

## 弹幕管理局限

相同内容默认30秒内去重，同用户默认8秒限频，均可配置；同用户0秒表示关闭限频。当前身份依据桥接提供的昵称，不能视为平台验证用户ID；相同内容跨观众也会去重，可能误伤普通问候。运行缓存有500条上限，停止、重启互动或更换绑定后清空。管理拦截计入过滤数，不计入后续收到/入队数；自发和消息ID重复保持原处理方式。

没有平台封禁/禁言权限，不读取或修改平台账号；不是独立语义审核模型，不能保证全部违规内容被识别。输出前检查继续保留。后续可接入可靠用户ID、问题优先级和人工待处理列表，再按实际成本与效果考虑独立审核模型；本轮不增加无明确收益的额外Agent。

## 资源自主性与阅读

能力与自动行为中的「自主选歌与选书」默认关闭，另需开启角色资源能力。开启后，普通聊天模型根据性格、偏好、习惯、当前语境和真实资源目录选择歌曲或书籍，不需要每次明确命令。自动场景选择继续有效；其他资源类别没有新增自主权限。

前端每次请求仍提供当前浏览器资源目录、歌曲ID与该角色最近12次成功操作。自动音乐/书籍选择会避开当前歌曲与最近3项；明确要求重播可以覆盖去重。否定要求、无效ID、种类不匹配或重复目录ID阻止操作。模型只能提出一个资源操作，实际执行仍由前端验证当前角色/场景版本和最新资源目录。

当自主开关启用或用户明确谈到读书时，浏览器从资源库已有同源/Blob TXT、MD书籍读取开头片段：最多4本、每本2000字符、最多读取约16KB并设置2.5秒超时。优先当前消息点名的书，其余按目录顺序。资源能力关闭时不读取片段；PDF/EPUB暂不抽取，外部URL不读取。服务端提示词也最多容纳4本片段，非书籍的excerpt忽略。

角色可以讨论已提供的片段，不能声称读完全文、读到未提供章节或听懂歌曲音频。书籍操作打开现有预览页，不新增整本通读、阅读进度或后台阅读循环；歌曲播放由现有播放器处理，仍受浏览器自动播放限制。当前时长/调用成本由所用文本模型决定，不额外增加规划模型调用。

这些能力用于携带浏览器资源目录的普通聊天。服务端独立直播仍不接收浏览器私有书籍正文或执行自动播放/切景，保持原有隔离；不是全天直播资源自动化。

对话、身体、阅读与资源的运行交接及回执语义见 [Agent 协作说明](AGENT_COORDINATION.md)。
