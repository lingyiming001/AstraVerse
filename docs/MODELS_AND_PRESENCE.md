# 模型路由与角色表现 · v0.2

## 使用方式

在「设置」或对话面板右上角打开设置。设置现已改为分组侧栏：外观与体验、角色表现、模型供应商、能力路由、多模态实验室、MCP 与工具和帮助中心。

1. 添加供应商，填写 API Base URL；使用准确的兼容 API 根地址，例如本地网关 `http://127.0.0.1:11434/v1`。远程地址要求 HTTPS。
2. 填写自己的 API Key（无鉴权的本地服务可留空），保存后立即生效。输入框会清空，后端只返回 `key_configured`，不会回传密钥。
3. 供应商在顶部横向切换；测试连接通过 `/models` 发现模型，或者手动添加准确模型 ID。
4. 添加聊天模型后点击卡片上的「保存并测试」或「测试对话」，向这一个模型发起一次真实极短聊天请求。结果显示回复、耗时与失败原因，不走备用模型、不自动重试；可能使用少量 Tokens。未声明文本能力的模型应在多模态实验室验证对应能力。
4. 给模型标记实际能力。标签是路由声明，不能把纯文本模型变成多模态模型。
5. 在能力路由中选择主模型；文本、图片理解、视频理解还可选择故障回退模型。保存。
6. 在实验室选择任务，准备输入，点击运行。输入仅在运行时发送给配置的供应商。

主聊天窗口使用已保存的 `text` 路由。没有显式路由且自动选择开启时，使用第一个启用的文本模型；可在能力路由顶部的「角色聊天模型」直接选择，或在供应商模型卡点击「设为角色聊天模型」后保存。没有可用文本模型时才使用明确标识的规则助手。回复标签显示实际模型，输入框下方显示当前聊天模型或本地模式。角色语音开关开启后，优先使用 `speech` 路由，没有语音模型时使用浏览器系统声音。模型语音播放和浏览器播报均驱动近似口型；不是音素级 viseme 对齐。

## 能力与适配协议

| 能力 | 实际请求 | 输入 / 输出 |
|---|---|---|
| text | POST /chat/completions | 文字 → 文字 |
| vision | POST /chat/completions | prompt + image_url data URL → 文字 |
| image | POST /images/generations | prompt，n=1，1024×1024 → b64_json 或 HTTPS URL |
| speech | POST /audio/speech | input + voice，response_format=mp3 → 音频字节 |
| transcription | POST /audio/transcriptions | multipart WAV/MP3 → text |
| video | POST /chat/completions | 浏览器按时序提取 4 张 JPEG → 文字 |
| video_generate | POST /videos | multipart prompt/model，4秒，1280×720 → 异步任务 ID |

视频任务使用 GET `/videos/{id}` 查询，GET `/videos/{id}/content` 获取完成内容。实验室提供手动刷新状态和完成后的播放器。当前只实现上述兼容协议，不代表任意供应商的原生 API 都可以直接调用；不同供应商的尺寸、声音、模型权限和视频接口可用性仍需实际匹配。不内置可用性不确定的模型 ID，也不预置付费密钥。Claude/Gemini 原生协议需通过兼容网关或后续独立适配器接入。

视频理解不是原生视频/声音推理：取 10%、35%、60%、85% 四帧，最长边压到 768px；可能遗漏短暂事件，没有视频声音输入。需要原生音视频理解时应新增供应商专用 adapter，不能把当前采样理解标成完整视频理解。

图片/音频输入最大 8 MB，视频最大 50 MB；只在浏览器处理原始视频。后端总附件 Base64 预算 12,000,000 字符，最多 8 个附件；视频输出预览最大 50 MB。生成请求（图片、语音、视频）不自动回退或重试，避免不确定结果后的重复计费。停止等待会取消浏览器等待，不承诺取消供应商已收到的任务。

当前使用非流式请求。超时 5–180 秒、文本最大输出 64–8192 tokens 可调。文本/图片/视频理解失败后按顺序尝试 fallback，响应包含实际 provider/model 与先前失败状态；生成失败返回可读错误，不回显上游原始诊断或密钥。

协议核对参考：[Chat Completions 图片格式](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[音频转写](https://platform.openai.com/docs/api-reference/audio)、[SDK 视频 multipart 适配结构](https://github.com/openai/openai-python/blob/main/src/openai/resources/videos.py)。这些链接仅用于接口结构参考，不构成对任何特定视频服务当前可用性的承诺。

## 配置与本地边界

- 配置默认位于 `.local/models.json`，不加入 Git；可用 `ASTRAVERSE_CONFIG` 指定路径。
- JSON 文件保存密钥，使用原子替换与文件权限 `0600`。这是本地明文权限保护，**不是加密保险库**；未来可换系统 Keychain/密钥管理服务。
- 查询接口、保存响应和校验错误不回传密钥；浏览器 localStorage 中不存密钥。留空保留已有密钥，明确点击清除后保存才清除。
- 初次无文件时可兼容 `LLM_*` 环境变量；一旦保存文件，文件中的配置优先。
- 远程 HTTPS，HTTP 仅允许 loopback，拒绝 URL 内凭据、查询、片段、私有非 loopback IP 字面量。没有完整 DNS 重绑定防御，因此仍仅限受信任的本机单用户使用。
- 写请求检查浏览器 Origin；此服务仍没有用户身份认证，不可直接暴露公网。

## 角色控制

舞台右侧「角色表现控制」打开侧边面板，保持舞台可见，方便即时调整。设置中的角色表现页提供同样的控件。

- 六种表情：自然、开心、好奇、低落、惊讶、放松，强度 0–1。
- 头部左右/俯仰、左右肩、左右肘、左右腿、身体倾斜，共 9 个关节参数。
- 姿态预设：自然站姿、伸展双臂、害羞招呼、思考片刻。
- 整体朝向 -180..180°；自然律动开关；视线跟随开关；呼吸幅度。
- 自然表现：平滑姿态插值、约 4.7 秒眨眼节律、轻微重心变化、胸身呼吸缩放、指针视线和头部跟随。
- 模型语音播报可按 Web Audio 实际能量近似张嘴，浏览器系统语音使用节律回退，面部表情同时改变嘴角、眼睛开合、眉毛、腮红和头部倾斜。
- 聊天支持明确关键词控制，例如「笑一个」「惊讶」「放松」「伸展双臂」「抬起左手」「低头」「跳一支舞」。当前动作识别仍是规则，不宣称 LLM 自主规划。

控制通过 REST → 执行器 → WebSocket 广播，同步给已连接浏览器；离线时仅做本地调整并显示状态。关节范围由 Pydantic 约束，部分 pose 参数可合并更新。滑杆按工具分别 debounce，避免不同类控制互相吞掉。

三位伙伴均从公开模型库加载真实 VRM 资产：星澜为 pixiv VRM1 官方示例、弥音为 CC0 Vita、绯月为 CC0 Vivi。VRM 0.x / 1.0 支持标准化骨骼姿态、表情、自然眨眼、目光和语音口型；实际表情依赖原模型预设。导入的静态 GLB 只支持整体朝向与移动，没有任意非 VRM 模型骨骼重定向。姿态目前是运行状态，后端重启会重置；未来可加入项目持久化。

## 新增接口与 MCP

- GET/PUT `/api/models/settings`：读取脱敏配置 / 原子保存并实时生效。
- POST `/api/models/probe`：保存后测试 `/models` 连接与模型发现（不代表推理成功）。
- POST `/api/models/test`：指定 provider_id / model_id，对已保存且启用的文本模型发送一次 max_tokens=32 的实际聊天验证，最多等30秒，返回 success/failed、耗时、回复预览和有限诊断；不回显密钥，不走回退。
- POST `/api/models/infer`：按 capability 路由多模态推理。
- GET `/api/models/video/{provider_id}/{job_id}`：查询视频任务。
- GET `/api/models/video/{provider_id}/{job_id}/content`：受限代理视频内容。
- `character.emote`：六表情 + intensity；`character.rotate`：已实现。
- 新增 `character.pose` / `character.presence`，MCP 共 17 个工具。

未实现的歌声、寻路和远程镜头仍返回明确的不支持；动作派发仍不等于浏览器渲染完成。

## 验证范围

后端测试使用隔离临时配置和 httpx MockTransport，覆盖配置/脱敏/权限、回退、图片/音频/视频请求协议、失败不重试、关节与表情约束。浏览器通过本地测试供应商验证供应商保存、发现、路由选择、文本与图片结果及角色控制。历史自动化未调用真实付费供应商。2026-10-17按用户本轮要求对现有qwen-plus做一次实际验证：返回「连接成功」，耗时754ms、16 Tokens；这只证明该模型在该时刻的基础调用成功，不代表其他模型或模态均已验证。


### 对话与音乐驱动

角色聊天带当前 Agent 最近4–20条独立会话（默认12，每条最多1500字），同一次文本请求返回回复与受约束performance数据。后端/前端验证情绪、手势、强度、时长，不执行自由骨骼脚本。模型不遵循格式时回退本地保守语境规则，不另发推理请求。用户的显式姿态/动作控制保留优先权。

音乐使用实际播放节点的Web Audio RMS/低频瞬变与启发式节奏估计，不上传音频。弱节奏采用缓慢摇曳，较强节奏增加肩臂幅度，静音/暂停逐渐收势。该功能为程序化动作混合，不是动捕或足部IK。设置可独立关闭表情响应或音乐动作。


### 角色专属 Agent

每个内置/导入角色按资源ID绑定Agent。设定含背景/性格/说话方式/关系/边界，表达参数影响表情、手势和音乐律动；专属模型必须是已保存、启用且具备text能力的目标。专属模型失效时明确提示，不静默切换；未指定时使用全局文本路由。

角色上下文由服务端SQLite按agent_id隔离，完整保存原文，主聊天加载100条；清空递增会话修订号，避免迟到回复写回。手写memory_notes是该角色的参考资料，不自动生成用户画像。聊天动作返回给浏览器，由仍处于前台的角色执行，再通过显式工具同步；后台旧角色只保存回复。配置与会话文件都在忽略的.local目录，0600明文，本地单用户范围不变。

### 本地插件与外部 MCP

角色 Agent 的 `allow_plugins` 控制是否接收明确的系统插件聊天指令。全局启用状态与系统权限在设置的插件中心管理。MCP 客户端独立使用全局插件权限，不冒用某个角色的聊天开关。插件执行走 Pydantic 白名单 schema，并以明确结果返回，不假装完成。初期提供 clock/calculator/notes/workspace/system/clipboard；仅前两项默认开启。当前插件输出直接显示真实数据，不额外调用大模型润色。

HTTP MCP 在主 API `/mcp/` 提供 `agents.list`、`agents.chat`、`controls.list/call`、`plugins.list/call`。Agent 对话复用独立上下文并通知浏览器刷新会话；可选 perform 仅作用于当前舞台，没有远程角色模型加载。模型费用与普通聊天一致。stdio 同步扩展角色/插件工具。

### 持久摘要与资源决策更新

`agent_memory.py`：每8条新增消息调度单次后台摘要，最多40条一批；使用当前角色模型、仅用户原话、来源ID验证。SQLite保留完整历史、累积线索和摘要，主聊天仍100条窗口。短期上下文与话题关键词匹配的旧线索/原话一起提供给聊天模型；直播专用链路不调用此记忆模块。清空/删摘要使用会话revision和memory generation双保护，防止迟到任务复活记忆。没有新模型连接或额外向量服务依赖。

资源控制器默认将泛泛选歌请求直接解析成真实曲目ID，并避开当前曲目。LLM可附受限resource_action，服务器/浏览器验证目录ID及kind；图片视频仅预览、歌词应用、不允许任意代码或删除资源。`danceMotion.ts`提供连续乐句编舞，与AvatarModel按dance权重混合，保留VRM骨架与减弱动态设置。


### 全身舞蹈与表演控制（2026-10-19）
- 主动舞蹈采用独立幅度（40–125%），不再被自动动作幅度为零影响。角色控制中可直接开始/结束。
- 16 拍编舞增加交替抬腿、屈膝、侧步、重心和胸胯反向转动、扩大手臂轨迹、延迟手腕与手指收放。按最低脚踝校准高度补偿，尚非足底锁定 IK 或动作捕捉。
- 简短明确的跳舞/停止跳舞聊天指令在前端立即执行，不依赖模型请求成功；复杂组合指令继续由现有资源与聊天链处理。
- 提供眨左/右眼、点头、歪头、张手与抚心预览；单眼预设缺失退化为双眼眨眼。中性表情下舞蹈自动微笑，聊天情绪优先。
- VRM 骨骼与表情由模型实际预设决定；静态 GLB 不支持人形骨骼舞蹈。减少动态效果仍优先，并显示提示。
- 本轮仅构建和 HTTP 就绪检查，视觉和动作验收由用户负责。

### 音乐音源生命周期修复（2026-10-19）
歌曲共用一个持久 audio 元素，切换、暂停和卸载时明确停止播放；忽略已取消播放请求的迟到错误。内置合成音乐按选中歌曲身份重建，页面渲染、播放进度和目录名称更新不会重建音源。清理时先断开输出并停止振荡器，再关闭 AudioContext，避免异步关闭期间继续发声。音量与循环单独同步，不重新触发播放。

### 表演调度与音频所有权（2026-10-19）

Agent依据已加载Live2D模型上报的动作组、表情和参数选择短指令，前后端均按能力白名单校验，model_key阻止旧角色回复控制新角色。原生动作期间，程序头身摆动淡出；动作窗口结束后渐进恢复，音乐律动平滑跟随。当前属于表演导演的基础调度，尚未接入真实舞蹈动作库或MotionSync音素口型。

音乐播放器使用同源Web Locks获取播放所有权，其他页面收到相同服务端播放广播时不会同时出声。文件播放和合成音均等待资源库初始化并受此所有权控制。Live2D SDK动作声音全局关闭，避免直接model3.json中自带Sound绕过播放器；角色TTS保持独立。旧页面须刷新后才具备该互斥机制。离线所有权检查覆盖重复抢占、释放和重新获取；实际听感由用户验收。


### 普通聊天与内容约束

普通聊天优先简短口语，角色身份、背景与文风只作为相关话题的背景记忆。不要生成舞台动作、抒情旁白、无关比喻或固定安慰套话；动作仍由独立的 performance 字段控制。统一交流规则追加到角色提示之后，不能由角色配置、记忆或用户指令解除。

前端输入即时提示并阻止发送；API 在资源或插件处理之前再次校验。统一模型入口覆盖聊天、模型实验室与语音合成输入；模型文本和转写输出经过检查，结构化 JSON 在解码后检查以避免 Unicode 转义绕过。被拦截的回复替换为中性提示，不朗读原始内容；普通聊天同时清除动作与资源指令。历史中已匹配违规词的消息不再送入模型上下文。

当前检查基于本地中英文词表，处理全角、零宽字符、中文分隔和部分英文标点变形。词表会严格拦截引用场景，不能覆盖全部隐晦攻击或新变体；模型提示同时禁止人身攻击，后续可根据实际误报与漏报扩展词表或接入语义审核。实现位于 `modules/conversation/policy.py`，前端即时校验位于 `shared/contentPolicy.ts`。

Live2D 动作面板默认折叠，移动到画布右下角；展开后限制高度，避免在角色面部上方显示常驻控制面板。

### 场景、表情补足与步行

场景世界新增六个本地组合场景：晨光卧室、暖灯卧室、午后公园、萤光公园、晴日教室、放学后的教室。家具、树木和灌木来自 Kenney 官方 Furniture Kit / Nature Kit（CC0），只保留所用 GLB 和原始许可；来源在 `public/scenes/NOTICE.md`。地面、墙面、黑板、路径、灯光及布局由项目组合生成，不是可自由行走的照片或六份第三方完整环境。

`features/scenes/sceneCatalog.ts` 登记资源、边界及家具障碍；`SceneEnvironment.tsx` 使用本地 GLB 组合环境。`.scene.json` 是内置场景标识与元数据，已有用户 GLB 导入方式保持兼容。`node apps/astraverse-web/scripts/build-scene-previews.mjs` 更新清单和 SVG 预览，`npm --prefix apps/astraverse-web run test:scenes` 验证资源、许可与碰撞约束。

舞台左下“场景与表现”控制环境氛围、表情特效和走动。卧室/教室有光尘，公园有日光微粒或萤光。表情特效默认为能力不足时补足：VRM 检查实际表情绑定，Live2D 检查有语义对应的表情文件；缺少当前情绪时显示心形、雨滴、疑问、惊讶或月牙。口型或少量基础参数不视为完整情绪表现。手动反复触发表情会重新显示短暂特效；可选择始终显示或关闭，减弱动态下仅保留静态情绪符号。

步行仅对加载成功且具备 hips、双侧大腿/小腿/脚骨骼的 VRM 开放。开启后切到场景取景，WASD/方向键或点击地面移动，提供程序步态、转身和脚底修正；不对 Live2D 或未识别的人形 GLB 模型伪造步行。减弱动态、切出创作页、失去窗口焦点或输入文字时不驱动行走。内置场景有平面边界和家具碰撞，点击路径是直接走向目标并在障碍处停止/沿边滑动，尚未实现寻路绕行、楼梯、多层地形或任意导入 GLB 的自动碰撞解析。

## 3D 角色休息动作

创作空间舞台和角色表现控制均提供“坐下、蹲下、睡觉、站起来”。这些动作要求 VRM 完整躯干与腿脚骨骼，静态 GLB 和 Live2D 不提供这些程序骨骼动作。普通“坐下”采用地面伸腿坐姿，“睡觉”为地面仰躺并闭眼；家具交互使用独立的床位与椅面锚点。姿态平滑切换，暂停走动并切换完整取景；睡觉抬高镜头，站起来后可继续走动。

聊天可直接说“坐下”“请蹲下吧”“躺下睡觉”“站起来”“醒来”，短指令无需调用模型；“不要坐下”或用户自述“我想睡觉了”不会直接命令角色躺下。REST/WS/MCP 的 `character.animate` 同步支持 `sit/crouch/sleep/idle`。

### 床铺与书桌交互

在卧室选择“上床睡觉”，或点击实际床铺，角色会切到场景取景并平滑定位到床上仰躺、闭眼。卧室和教室可选择“坐下学习”或点击书桌：角色面向对应桌子坐在椅子上，膝盖弯曲，按实际髋骨位置对齐椅面，桌面出现打开的书。教室点击不同书桌会使用对应椅位；动作栏默认使用前排右侧书桌。

也可直接说“上床睡觉”“到床上休息会”“坐在桌前学习”。这些明确短指令由本地规则响应；当前没有对应家具时提示先进入卧室或教室，不触发任意模型生成的坐标。“站起来”、其他动作、切换角色/场景或隐藏舞台会释放家具状态并回到场景中央的安全地面。静态 GLB、Live2D 和缺少完整人形骨骼的模型禁用家具动作。

内置弥音、绯月为 VRM 0，星澜为 VRM 1。VRM 0 的模型朝向修正不会改变归一骨骼的原始坐标轴，动作因此需要同时反转 X/Z 旋转，否则待机放手会变成举手。初始化和逐帧动作均通过 `rigPose.ts` 统一修正；`test:furniture` 使用三个实际模型的骨架检查双手低于肩膀，并检查家具范围、指令和退出状态。

当前家具交互为内置场景固定锚点与程序姿态，使用平滑位置过渡；未加入攀床动作、绕障寻路、手部 IK、任意导入场景的家具识别或跨客户端家具状态同步。床位配置位于 `features/scenes/furniture.ts`，姿态位于 `features/stage/restPose.ts`。验证：`npm --prefix apps/astraverse-web run test:furniture`。

### 渲染异常与恢复

模型加载中、失败或骨骼能力不足的提示，以及表情特效，均由 Canvas 外的普通 React DOM 渲染，避免独立 Html 根节点在模型就绪或切换时重复清理，触发 `removeChild` 异常。模型加载状态按资源 URL 区分，旧请求取消后不覆盖新状态。

角色加载失败时可点击“重新加载模型”；场景或整个舞台发生渲染异常时可点击“重新加载舞台”，重试会清除 GLTF 失败缓存再重建舞台。切换角色、场景或资源可见性会自动解除旧的错误状态；正常切换场景时保留既有模型，不为重置错误边界反复重载角色。模型和场景文件本身损坏时仍会显示失败，可修复文件后重试或切换资源。

### AI 对话驱动实际家具交互

对话请求现在携带当前场景的真实交互清单 `scene_interactions`（ID、用途和名称），只为可用人形角色生成。卧室列出床、椅子与书桌；教室四组桌椅均可指定；公园列出左右长椅。AI 可在 JSON 顶层返回 `stage_interaction: {target_id, kind, scene_id}`，用途为 `sleep/study/sit`。后端只接受清单中的目标和当前场景，不接受生成的任意坐标；前端根据自身家具布局解析并执行。

明确指令如“你到床上休息一会吧”“坐在右边长椅上休息”“去书桌前学习吧”走本地规则，不调用模型。未指定位置时优先最近的同类家具；左右、前后排可用于筛选。普通对话中的 AI 提议也能执行：模型遗漏结构化动作、只说“我轻轻躺下／坐在椅子上”时，后端兼容识别第一人称动作并校验家具；梦境、小说、建议用户躺下、否定和用户自述不会这样转换。角色关闭资源操作权限时不执行 AI 家具操作。

收到动作时会再检查角色、场景、目标和人形能力，并核对请求期间有无新的手动姿态指令；过期回复不会覆盖用户操作。聊天显示“已执行：床上躺睡／桌前学习／椅上坐下”，执行失败则明确说明没有执行。缺少床椅或角色不支持时也会说明，不能仅生成已经睡下的描述。

舞台和表现控制的“坐下”在有椅子时优先坐椅，“睡觉”在有床时优先上床；也可点击实际椅子、长椅、桌子或床铺。长椅使用独立坐姿和椅面校准，镜头从步道侧取景，避免树遮住角色。范围仍为内置场景的已登记家具，不自动识别导入 GLB 内的椅子，不包含盖被子、攀床、寻路或手部 IK。

### 角色隔离、能力与配件

舞台动作栏的“能力与配件”提供六种基础表情、表情强度、眨眼、走路、跑步、哼唱、停止与耳机。能力按当前模型的真实骨骼和表情绑定开放；耳机需要头骨，哼唱需要口型绑定，走跑需要完整腿脚骨骼。减弱动态会禁用移动能力。

聊天可说“跑起来”“走两步”“唱首歌”“戴上耳机”“摘下耳机”“停下来”。明确指令走本地规则，普通 AI 也可返回经过能力白名单校验的 character_ability。自动走跑使用当前场景内经过碰撞检查的一段路线往返；键盘 WASD/方向键可接管，按 Shift 快跑，仍不包含绕障寻路。

哼唱是 Web Audio 实时合成的原创无词旋律，有实际音频输出及随音量变化的口型，不是歌词演唱、人声生成或歌曲翻唱。开始时停止朗读并暂停音乐；停止、切换角色、离开创作页或开始冲突动作时释放音频，音量跟随播放器设置。耳机使用本地程序网格，跟随头部位置和方向，可与坐下、睡觉、移动及表情组合。

每个角色使用独立身份与记忆。新浏览器控制命令携带 actor_id/client_id，过滤旧角色事件和本客户端的重复回声；聊天请求同时核对角色、模型、场景与交互版本，迟到回复不能覆盖新角色或手动操作。角色切换清理表情、配件、移动和哼唱；提示词固定当前角色身份，防止引用其他角色内容改变身份。

动作状态区分主要活动、面部表现和配件。走跑、跳舞、休息、家具交互、哼唱等主要活动互斥；普通聊天提议不能打断已进行的主要活动，明确用户指令可以切换，面部表情和耳机可独立叠加。旧版未带 actor_id 的 REST/WS/MCP 命令仍是全局舞台控制；移动、哼唱和配件尚未实现跨客户端完整状态同步。

### Live2D 全屏大小

Live2D 进入沉浸全屏后默认按普通适配比例放大到135%，左下“人物大小”支持75%–200%调整。普通模式和全屏分别保留当前页面内的缩放值，退出全屏恢复普通比例；放大优先保留模型上沿，允许下半身超出舞台，以便看清面部。窗口尺寸变化会重新适配，不重新加载模型。
