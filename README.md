# AstraVerse ✧

原创 AI 虚拟伙伴与 3D 创作空间。React 19 / TypeScript / React Three Fiber + Python FastAPI + 官方 MCP Python SDK。当前交付是**本地单用户 MVP**，并非提示词中全部商业化能力。

## 项目结构

- `apps/astraverse-web/`：`astraverse-web`，React 19 + TypeScript + Vite 前端。
- `apps/astraverse/`：`astraverse`，Python + FastAPI 后端，项目配置见 `pyproject.toml`。
- `deploy/`：依赖安装、构建部署、服务管理与 Docker 配置。

根目录只保留项目说明与应用目录。前端依赖及锁文件由 `apps/astraverse-web/` 管理，Python 依赖及虚拟环境由 `apps/astraverse/` 管理；部署入口集中在 `deploy/`，不通过根目录 npm 脚本转发。运行数据保存在 `.local/`。代码职责见 [代码组织说明](docs/CODE_STRUCTURE.md)。

## v0.3 界面与自然表现

主界面扩大舞台与对话，新增沉浸模式、招呼/微笑快捷操作；MCP 和帮助中心统一位于设置。设置分为偏好、智能与模型、连接与支持，外观/语音/动效自动保存在浏览器。角色增加眼白、虹膜、瞳孔、鼻耳、手指与头发细节，自主眨眼采用不等间隔，支持眼神停留、轻微目光游移、头发滞后和实际模型语音能量驱动的近似口型。仍是原创程序化角色，并非写实数字人或音素级口型。

当前本机构建版入口：http://127.0.0.1:5174；重新构建并运行使用 `./deploy/start-local.sh`。不公开发布，后端仍为本地单用户 API。

## 本地启动

需要 Node.js 22.12+、Python 3.12+。在仓库根目录执行：

```bash
bash deploy/setup.sh          # 安装前后端各自的锁定依赖
bash deploy/start-local.sh    # 构建并启动/更新两端
python3 deploy/local.py status
python3 deploy/local.py stop
```

打开 http://127.0.0.1:5174。接口文档 http://127.0.0.1:8000/docs。更多部署说明见 [deploy/README.md](deploy/README.md)。

开发时在两个终端分别运行：

```bash
apps/astraverse/.venv/bin/python -m uvicorn astraverse.api.application:app --app-dir apps/astraverse/src --host 127.0.0.1 --port 8000
npm --prefix apps/astraverse-web run dev
```

开发前端地址为 http://127.0.0.1:5173。验证命令：

```bash
npm --prefix apps/astraverse-web run build
npm --prefix apps/astraverse-web run test:scenes
apps/astraverse/.venv/bin/python -m pytest -c apps/astraverse/pyproject.toml apps/astraverse/tests -q
```

## MCP 接入

在支持 MCP stdio 的客户端中添加以下配置，将 `/absolute/path/AstraVerse` 替换为本项目绝对路径，并先启动 API 和浏览器：

```json
{
  "mcpServers": {
    "astraverse": {
      "command": "/absolute/path/AstraVerse/apps/astraverse/.venv/bin/python",
      "args": ["-m", "astraverse.integrations.mcp.stdio"],
      "env": {"ASTRAVERSE_API": "http://127.0.0.1:8000"}
    }
  }
}
```

17 个舞台工具及 4 个角色/插件工具均可发现。移动、动画、跳跃、舞蹈、播报、预设场景、音乐、状态查询已接入。表情、9 关节姿态、整体旋转与自然表现均支持内置角色；歌声合成、导航、远程镜头明确返回 501，未伪造成功。`dispatched` 仅表示 API 广播完成，尚无浏览器执行 ACK。音频播放需浏览器先发生用户手势。

## 已知边界

当前共享单工作空间内存状态，重启会重置，不能公开部署为多用户服务。浏览器常规操作以本地状态为主，动作工具走 API；完整双向状态版本合并待实现。GLB 为静态预览；VRM 使用标准化人形骨骼与预设表情，Live2D 使用独立 Pixi 画布及 Cubism Core；尚未处理非 VRM 模型的通用骨骼重定向、物理碰撞、自动寻路、歌声合成、实时语音输入与实时语音、账号、数据库、云文件、版本管理与完整编辑器。GLTF 外部资源未支持。恶意/复杂 GLB 的 GPU 资源消耗仍需沙箱与预算限制。界面使用系统字体，不依赖远程字体下载。

完整产品方案、协议、数据模型、分阶段验收与授权说明见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)。容器开发运行见 [deploy/README.md](deploy/README.md)。

## 清新陪伴界面与资源库

默认青瓷，另有云铂、雾蓝、暖砂、曜石、深海六套外观；顶部选择器与「设置 → 外观」均可切换。舞台支持人像、全身与场景视角，使用柔和光照和干净背景呈现角色，右侧独立对话，底部保留播放器。

角色、场景、音乐、书籍和资源库使用统一的五列表格页面，支持搜索、来源筛选、名称排序及20/50/100项分页。每行保留主要操作，编辑、替换、删除收进更多菜单；编辑和删除在独立对话框完成。图片与视频可展开预览，LRC可重新应用。全局导航、设置页和列表共用[界面布局规范](docs/PRODUCT_UI.md)；上传文件保存在当前浏览器，支持朗读的书籍全文另存本机服务，不同步到云端。

在舞台说「放一首歌」「换个场景」「换个角色」，本地资源控制器会列出真实目录，请用户点选、按序号选择或随机选择后执行，并配合动作。普通聊天继续使用文本模型路由；只有角色、场景、音乐的目录元数据进入聊天请求，媒体二进制与 Blob URL 不会发送给模型。图片/视频在此版本是本地预览资源，不由聊天控制器执行。

三位伙伴均使用真实 VRM 模型：星澜使用 pixiv 官方 VRM1 示例，弥音使用 Vita（β AvatarSample_3），绯月使用 Vivi（β AvatarSample_2）。后两者为 CC0，完整来源与授权见资源库和 `apps/astraverse-web/public/models/NOTICE.md`。模型文件已随项目打包，本地启动后不依赖外部模型 CDN；可导入自己的 VRM 替换。VRM 表情取决于原模型提供的预设，GLB 仍为静态预览。

## 对话表情与音乐律动

「角色表现控制 → 互动与音乐」可开关情绪响应、音乐律动，并调整自动动作幅度。手动关节、表情和动作暂时优先；系统减弱动态会停用自动动作。

角色 Agent 在同一次模型请求中返回回复和受约束的情绪/手势数据，结合近期上下文选择自然、开心、好奇、低落、惊讶或放松表情，以及点头、侧头、掌心展开、手放胸前等小幅动作。前后端均验证白名单与数值范围；兼容端点不返回结构化数据时使用本地保守辅助。资源控制仍走既有真实目录执行流程，不由模型表情字段执行任意工具。

Web Audio 分析当前实际播放的上传音频或内置合成音源，提取 RMS 强弱、低频变化及启发式节拍估计；安静段减少幅度，无稳定节拍时按缓慢流动方式摇曳，暂停后平滑收势。不是精确 BPM 分析、动捕或专业编舞。舞姿由胸腰、肩肘、手腕、手指及轻微重心变化组合，语音继续使用实际音频 RMS 近似驱动口型。


外观采用完整主题色板：中性底色区分页面、侧栏、卡片与输入层，低饱和强调色只用于主操作和选中状态，成功/错误/处理中使用独立语义配色。六主题共用 `themes.ts` 的颜色变量，`palette.css` 将旧组件接入相同色板，保持原主题 ID 和浏览器偏好不变。主题预览展示各自真实表面层次，3D 模型与媒体不作反色处理。


## 角色专属 Agent

「设置 → 角色设置」或舞台的角色设置按钮可编辑当前角色，也可选择其他角色。界面分为「基本设置 / 直播设置 / 更多设置」：基本设置只展示名字、一句话介绍、性格和说话方式，其余人设细节按需展开。已有角色配置无需重新填写，详见[角色设置说明](docs/AGENT_SETTINGS.md)。

「更多设置」按「声音与表现、记忆与资料、模型设置、能力与自动行为」归类，默认跟随已有全局模型；独立模型、资料档案、动作和灵感选项按需展开。合成语速使用播放速率，系统语音音调只影响浏览器TTS。表情和动作仍受全局开关与手动优先控制。

设定保存到被 Git 忽略的 `.local/agents.json`，独立会话保存在 `.local/agent-memory.sqlite3`，文件权限 0600，均为本机明文。完整保存每角色的聊天原文，聊天框加载最近 100 条消息，上下文 4–20 条（默认 12，每条截断 1500 字）。关闭「保留独立会话」后新消息不写入历史，旧记录可单独清空；手写专属记忆仍会随该角色的请求发送。清空有确认并取消尚未完成的旧会话写入。历史资源选项会标记为过期，避免重放旧操作。

当前实现是角色人设、模型选择、隔离会话与受限表现控制的组合，不自动生成长期用户画像。切换角色后，迟到回复只进入原角色会话，旧角色动作与语音不会作用到当前舞台；MCP 的显式控制工具维持原行为。删除模型资源不会自动删除对应的 Agent 配置与会话。

### MCP HTTP 与插件中心

API 启动后，官方 MCP SDK 的 **Streamable HTTP** 地址为 `http://127.0.0.1:8000/mcp/`。无需单独启动 MCP 进程。打开「设置 → MCP 与工具」可复制 HTTP/stdio 客户端配置；实际配置 JSON 也可通过 `GET /api/mcp/config` 获取。客户端字段格式以各应用为准，HTTP 服务器地址保持上述地址。

```json
{
  "mcpServers": {
    "astraverse": {
      "type": "http",
      "url": "http://127.0.0.1:8000/mcp/"
    }
  }
}
```

HTTP MCP 提供以下工具：

| 工具 | 能力 |
| --- | --- |
| `controls.list` / `controls.call` | 获取真实舞台工具参数规范，移动、旋转、表情、姿态、场景及音乐控制 |
| `agents.list` | 读取角色 ID、名称和身份，不暴露记忆笔记 |
| `agents.chat` | 与指定角色交流，使用该角色模型、设定、独立会话；可能产生模型费用 |
| `plugins.list` / `plugins.call` | 查看插件及参数规范，调用已经启用的插件 |

`agents.chat` 参数示例：`{"agent_id":"character-0","message":"你好","perform":false}`。HTTP 可显式设置 `perform:true` 将表情与明确动作派发到当前舞台；不会自动切换角色或播放语音。浏览器通过 WebSocket 更新角色会话。stdio 入口统一为后端模块 `astraverse.integrations.mcp.stdio`，包含 Agent 与插件工具；stdio 聊天只返回回复，不自动演出。

当前服务限定 **loopback 本机单用户空间**，连接它的本机应用共享会话与已授权插件权限。没有公网认证和多租户隔离，请勿将本地端口直接对公网暴露。角色/音乐动作需要浏览器保持打开，音频仍受浏览器用户手势限制；`dispatched` 不代表浏览器完成播放或渲染。

「设置 → 插件中心」提供六类内置插件：

| 插件 | 默认 | 能力 |
| --- | --- | --- |
| 时间与日期 | 开启 | 本机时间与时区 |
| 计算器 | 开启 | 受限算术表达式，无 eval、代码或 shell 执行 |
| 本地便签 | 关闭 | 保存、列出和读取专用便签，同名覆盖 |
| 工作文件夹 | 关闭 | 列出和读取 `.local/plugin-workspace/` 内普通 UTF-8 文本，单文件最多 64KB |
| 系统信息 | 关闭 | 操作系统、架构、运行时及目录所在磁盘可用空间 |
| 系统剪贴板 | 关闭 | macOS 文本读取与写入 |

启用时展示实际权限，停用后阻止后续调用。插件权限对所有本机 MCP 客户端生效；每位角色也可在「角色设置 → 更多设置 → 能力与自动行为」关闭自己的聊天插件能力。设置写入 `.local/plugins.json`（0600）；便签位于 `.local/plugin-workspace/notes/`。插件结果可能随该角色聊天记录存入 SQLite，请勿在不希望留存的会话中读取敏感剪贴板。

聊天可直接发送：`现在几点？`、`计算 (128 + 64) / 3`、`查看系统信息`、`列出便签`、`读取便签：灵感.txt`、`读取剪贴板`、`复制到剪贴板：你好`、`列出工作文件`、`读取工作文件：example.txt`。保存便签使用两行：

```text
保存便签：灵感.txt
今天想到的新点子
```

这些为明确、可审查的指令路由，不由模型生成任意系统操作。当前插件是随项目交付的内置插件，不安装不受信任的第三方代码；开发者可在 `apps/astraverse/plugins.py` 的目录、Pydantic 参数 schema 和处理器中注册新能力。启用插件不会向 MCP 客户端授予修改插件权限的工具。

### 直播平台与角色弹幕互动

1. 打开「设置 → 直播平台」，新增直播间，选择平台、房间号、接入方式与回复规则。保存配置会暂停现有连接。
2. 回到角色聊天框，展开「直播弹幕」，选择直播间，点击「绑定当前角色」，然后「启动互动」。一个直播间同时绑定一位角色，可将不同直播间绑定不同角色。
3. 默认只在本地弹幕面板回应；角色在当前舞台且未处理用户聊天时会做表情，朗读还需同时开启直播间语音和聊天语音。未显示的角色仍可回复文字。
4. 可设置触发关键词、5–120秒回复间隔。回复使用角色专属文本模型或全局路由，可能产生费用；没有模型时明确标注本地规则回应。

直播弹幕面板可复制透明字幕源地址，添加为 OBS 等直播软件的浏览器源（建议 1920 × 1080）。字幕只显示此直播间新产生的角色回复，短暂显示后自动消失；预览页不会重放历史回复。直播软件须能访问本机 Web 服务。该源只读取本地回复事件，向平台发布画面仍由直播软件负责。

**平台接入情况**：Twitch 实现官方 IRC over TLS 直连（`irc.chat.twitch.tv:6697`），需本人授权的机器人账号登录名及 OAuth 用户令牌，读取需 `chat:read`，回发还需 `chat:edit`。配置中可主动允许自动发回平台，默认关闭。登录令牌保存在 `.local/live.json`（0600），GET 配置不返回令牌。[Twitch 官方协议与授权说明](https://dev.twitch.tv/docs/chat/irc/)。Twitch 推荐新应用优先考虑 EventSub；本版使用已公开的 IRC 接口提供基础文字互动。

B站现支持官方互动开放平台签名鉴权、项目与长连双心跳、弹幕接收和场次结束；需要获批项目及主播身份码，官方接入不提供通用弹幕发送，角色用本地语音/字幕回应。YouTube 默认使用官方 StreamList 持续流接收并按令牌续传，保留可选REST轮询，支持授权回发、过滤首次历史与OAuth自动刷新；长时间运行仍需核对项目配额。Twitch 新增启动及每小时授权验证、可选自动续期。三个平台都保留桥接方式；设置页可检查已保存授权，B站授权需启动官方场次才能验证。详见 [三平台配置与联调](deploy/PLATFORM_CONNECTIONS.md)。

抖音、斗鱼、虎牙和其他平台提供**统一桥接入口**，需要另一个具有对应平台权限的弹幕采集程序。点击直播间的「显示桥接配置」获取本机 POST 地址、Bearer 私有令牌及消息格式：

```json
{"id":"platform-unique-message-id","user":"观众昵称","text":"星澜，你好","room":"12345","is_self":false}
```

发送到 `/api/live/channels/{id}/incoming`，携带 `Authorization: Bearer <token>`。房间必须匹配，启动并绑定后才接收。桥接连接仅在首次收到有效弹幕后标记已接收；启用桥接配置本身不会与平台建立连接。`deploy/live-bridge.py` 是给已有授权采集器的 JSONL 转发适配器，**不包含平台抓取或登录逻辑**：

```sh
# 将私有令牌放入 ASTRAVERSE_LIVE_TOKEN 环境变量，避免放在命令参数中。
# collector-command 代表你已有的平台授权采集程序，输出 id/user/text JSONL。
collector-command | apps/astraverse/.venv/bin/python deploy/live-bridge.py --channel <配置ID> --room <房间号>
```

若允许发回平台，桥接可用同一令牌轮询 `GET /api/live/channels/{id}/outbox?after=<sequence>` 获取待发回复，按 sequence/id 去重并通过自己的平台授权发送。`--poll-replies` 可将新回复输出到 stdout JSONL，仍需单独的授权发送程序；队列不是平台送达确认，暂停/重新绑定/重启会丢弃待发队列。桥接脚本不自动重放历史回复。所有服务保持本机 loopback，不向公网开放此私有入口。

直播输入不经过资源控制或系统插件。使用角色的公开人设及当前直播间最近6条上下文，**不读取私人聊天或专属记忆笔记**。输入去重最近500条，等待队列20条，超过90秒的排队弹幕跳过；全局并发模型请求最多2个。Twitch发言跨直播间串行限速，带 `[AI]` 前缀并限制字节数。直播最近80条显示事件及上下文仅存在内存，服务重启后需手动启动连接。没有凭据时不会连接平台；未进行真实直播或付费模型联调。

### 自主选歌、舞蹈与长期记忆

- 对角色说“给我放首歌”“来一首歌吧”，会直接从当前真实音乐库选一首，并尽量避开当前曲目；说歌名会按名称点播，说“有哪些歌”仍展示目录供选择。资源库为空时明确提示导入。没有上传的资源不会虚构为可播放内容。
- 自然语言模型现在可在受限 JSON 中选择真实目录 ID，服务端/浏览器再次验证；可操作音乐、场景、角色、歌词，以及在资源库打开图片/视频预览。媒体二进制不会自动上传给文本模型。播放仍取决于浏览器音频权限与文件是否可用。
- “跳一支舞”使用连续乐句：重心移位、躯干反向转动、左右手错相展开、手腕跟随、轻微换步与膝踝配合；有音乐时跟随实际节奏估计，无音乐时使用内部节拍。动作幅度和角色气质影响舞姿，支持减弱动态。它仍是程序编舞，尚未实现动捕或足部IK。

「设置 → 角色设置 → 更多设置 → 记忆与资料」新增**自动整理长期记忆**及记忆面板。开启记忆时，之后的完整原文一直保存在 SQLite，直到用户清空；聊天页仅加载最近100条，“查看完整历史”可分页读取更早原文。旧版本曾因100条上限而已删除的记录无法恢复。

自动摘要默认开启：约每4轮（8条新消息）触发一次后台整理，每次最多处理40条原文；使用角色自己的文本模型或全局路由，摘要请求可能产生费用。已有较长历史会随后续整理逐批处理，也可点击“现在整理”。无模型时仅使用明确原话摘录，界面会区分“AI摘要”和“原话摘录”；失败不删除原始记录或旧摘要。

数据库新增 `agent_memories`（摘要、进度与清除代次）和 `agent_memory_facts`（长期线索及原话ID）。记忆线索持续保存，面板展示最近50条；聊天时以当前话题关键词从全部线索与旧用户原话中检索，再结合近期上下文回应，不是向模型发送全部聊天记录。模型生成的摘要可能有误，可点原话ID核对。

“删除自动记忆”清除摘要和线索，保留原文/手写笔记，并阻止旧归纳消息重新自动提取；“清空会话”删除全部原文与自动记忆，同时使正在处理的旧摘要失效。关闭聊天记忆后不读取自动摘要、不新增会话记录。关闭自动摘要只停止后续整理，已有记忆仍可供开启记忆的私聊参考。直播弹幕始终不读取这些私人内容。保存位置仍为 `.local/agent-memory.sqlite3`（0600，本机明文）。

### 聊天输入与语音回复

聊天输入区采用自动增高的多行卡片：Enter发送，Shift+Enter换行，中文输入法选字时不会误发送，最多4000字。底部「语音回复已开启/关闭」明确显示自动播报状态，选择保存在浏览器；关闭会取消本机等待并停止播放，等待回复期间关闭也不会在回复到达后重新播放。

开启后，新角色回复优先走已配置的speech路由，未配置时使用浏览器系统中文语音，沿用该角色语速/音调等设定。语音生成、播放及失败状态显示在输入卡片，支持随时停止；每条角色回复下的「朗读」可单独重听，不会开启自动播报。语音模型可能产生供应商费用，系统语音依赖浏览器/操作系统支持。

### 居中取景、场景切换与舞蹈控制

创作空间中的角色开启资源操作权限并接入聊天模型后，可按对话语境主动切换真实资源库里的场景，例如准备睡觉时选择卧室、散步时选择公园、学习时选择教室。普通提及地点不会要求切换；模型选择仍取决于语境。当前场景不会重复应用，用户说“留在这里”或“不换场景”时保持原场景。也可直接说“去公园”“去卧室睡觉”“去学校”，由本地资源控制器选择对应场景，无需模型推理。

舞台使用单列布局，模型按自身包围盒水平居中；镜头目标跟随角色位置，按视口比例计算取景距离，减少窄视口或角色移动后被裁切的情况。右侧重置按钮可居中并恢复正面视角；仍支持拖动旋转和滚轮缩放。跳舞时自动使用全身取景，结束后回到用户选择的人像/全身/场景模式。

可直接说“换个场景”“带我去森林”“去夕阳天台”“切换到月球”，角色只从真实场景目录选择，默认避开当前场景；也可说“有哪些场景”查看列表。上传场景可按实际名称切换。切场景时会开启场景展示；正在跳舞时保持舞蹈，支持识别“换个场景跳舞”等组合指令。

舞台左下「场景与表现 → 快速切换场景」也能直接选择六个内置场景，Live2D 角色会留在场景前景。点击 Live2D 角色可触发模型实际提供的触碰动作或表情；减弱动态设置会停用触碰动作。

本机另外安装了 [Open-LLM-VTuber](https://github.com/Open-LLM-VTuber/Open-LLM-VTuber) 使用的 Live2D 官方样例 Mao PRO 和 Shizuku。进入「虚拟角色」即可选择；两款样例只在本地模型包存在时显示。模型包已放入 `apps/astraverse-web/public/models/live2d/` 并忽略 Git，来源、修改与许可见各目录 `NOTICE.md` 和 `LICENSE-Live2D.md`。在其他机器使用需按官方样例条款自行安装。

舞蹈更新为预设16拍动作段落，用周期三次插值衔接侧步、收势、描臂、展开、镜像动作和手腕收尾；以稳定节拍推进，音乐仅平滑调整速度，不把每次节拍检测跳变直接施加到关节。开始舞蹈时释放原有手动姿态和身体转向，减少举手姿势残留；不再叠加大幅连续上下弹动。舞台可直接开始/结束舞蹈。当前仍为程序编舞，不是动捕或足部IK；效果由用户实际模型和视觉验收决定。

### 平台共享模型与角色专属模型

「设置 → 平台模型」管理所有角色都能选择的供应商、密钥与模型；平台「能力路由」设定共享默认值。原有平台配置和密钥保持不变。

「设置 → 角色设置 → 更多设置 → 模型设置 → 配置此角色的独立模型」可给当前角色单独新增供应商、密钥、模型和七类能力路由。该界面复用模型发现、手动添加、保存、连接测试和多模态实验室；主动点击测试可能产生模型费用。角色模型不会出现在其他角色的专属模型库，也不会改动平台模型。

在该角色「模型设置 → 聊天使用的模型」选择并保存：

- **平台共享 · 跟随平台文本路由**：使用平台默认主模型与备用链。
- **指定平台共享模型**：从平台库选择一个已启用的文本模型。
- **角色专属 · 跟随本角色文本路由**：使用该角色库中的主模型与备用链。
- **指定角色专属模型**：固定使用该角色自己的一个文本模型。

聊天、长期记忆摘要、直播和 MCP Agent 聊天使用同一来源；选择不可用的专属文本模型时明确报错，不会静默改用平台模型。使用角色专属来源时，语音等其他能力优先使用该角色对应路由；缺少该能力路由时可继承平台配置。平台和角色都没有语音路由时，朗读仍使用浏览器系统语音。

角色配置新增 `model_scope: platform | character`，旧数据默认 `platform`，旧的固定模型选择继续指向平台库。专属模型保存在 `.local/agent-models/<agent_id>.json`（0600），与平台 `.local/models.json` 分离。密钥仍只写不回传；留空保存保留该层原密钥，可显式清除。当前是本机单用户的配置作用域隔离，不是多租户权限系统。

API：平台原 `/api/models/*` 保留；角色库使用 `/api/agents/{agent_id}/models/{settings,probe,test,infer,...}`。`/api/agents/{agent_id}/model-resolution?capability=speech` 返回有效来源与是否配置，不返回密钥。普通模型推理请求可带 `agent_id` 以采用该角色有效能力路由。

### 资源库统一增删改与书籍库

音乐、角色、场景、图片、视频、歌词和书籍均可在列表中**导入、编辑名称/描述、替换源文件、删除**。编辑和删除不再限制为上传资源。角色名称最多40字，并同步到该角色Agent；替换文件保留资源ID及原有名称/描述，角色Agent配置与聊天档案不会因换模型或删除模型被抹除。

内置资源删除是从**当前浏览器资源库移除**，不删除随应用交付的源文件；删除标记和元数据修改保存在本地，刷新后不会重新出现。上传资源的文件和元数据保存在 IndexedDB，删除会移除该浏览器中的副本。当前使用的角色或场景删除后选择其余可用项；删空后显示空状态，音乐删空会暂停播放。聊天只获取可见资源目录，迟到指令也重新检查目录，不使用已删除条目。

新增侧栏「书籍库」与资源库书籍分类，支持 TXT、Markdown、PDF、EPUB 导入（单文件默认50MB，可在文件资源设置调整）。TXT/MD支持本机纯文本分页预览，PDF由浏览器内置查看器展示。新增[整本朗读与持久书签](docs/BOOK_READING.md)：20MB以内TXT/Markdown/无加密EPUB可由角色分段朗读至正文结尾，按角色和书籍保存进度，只有语音完整播完才推进位置，支持暂停、继续、跳章、从头重读和直播读书。全文另存本机服务，文本模型只获得附近有限原文，不凭书名声称读完整本；语音服务每次只接收当前朗读片段。

库目录覆写与删除标记：localStorage `astraverse-library-catalog-v1`；文件和对应资源元数据：IndexedDB `astraverse-library`。这些属于当前浏览器/当前站点的本地资源，清除站点数据会移除导入资源与修改记录。后端模型设置、Agent和聊天数据库独立保留。

### 资料与记忆检索（RAG）

聊天和直播可检索资料库原文及来源明确的角色记忆，回答下方展开参考片段。书籍库的“资料检索”提供状态与重建入口；默认全文检索，配置平台“向量检索”模型后可开启语义检索。支持 TXT/MD/EPUB、文字 PDF、DOCX、SRT/VTT，沿用角色私有权限与公开直播限制。配置、索引失效及本机存储说明见 [RAG 使用说明](docs/RAG.md)。
