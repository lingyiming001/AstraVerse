# Agent 对话、身体、阅读与资源协作

本轮以现有角色聊天为入口统一交接，不增加角色配置项，也不增加数字人功能。

每轮最多一个主要操作，优先级为资源操作、明确的场景互动、角色能力，再到独立身体动作。主要操作存在时会移除冲突的身体动作和姿态指令。普通聊天保留已经进行的坐姿、睡姿、走动、舞蹈与阅读；只有用户明确提出身体变化时才调整。角色关闭资源工具时，身体和资源操作都不能绕过权限。小幅表情仍服务于对话，但休息状态会限制大幅手势，手动控制窗口优先于自动表演。

“唱首歌”按角色哼唱能力处理，由模型结合意愿和已支持能力判断；“播放歌曲”走真实资源目录。请求“放歌并跳舞”时，在支持相应身体姿态的模型上，先等待浏览器确认指定音源开始播放，再启动后续舞蹈；音乐失败或手动改变身体时不执行这一步。

## 浏览器执行回执

后端生成操作计划时创建角色专属操作ID；浏览器执行后通过 `POST /api/agents/{agent_id}/operations/{operation_id}` 回报结果。状态区分如下：

| 状态 | 含义 |
| --- | --- |
| pending | 计划已生成，尚无浏览器结果 |
| accepted | 已提交加载或阅读任务，不表示渲染完成、内容已播完 |
| confirmed | 浏览器确认目标音源播放，或已应用相应身体状态 |
| failed | 资源或操作没有执行成功 |
| cancelled | 手动操作、角色或场景变化使较早计划失效 |

音乐确认核对的是请求的音源、非暂停/结束状态与媒体就绪程度，不会用上一首仍在播放的歌曲充当成功。此确认不代表音响设备一定发出了可听见的声音。场景、角色和歌词加载先按accepted处理，不把开始加载等同于加载成功；阅读位置仍只在每段实际语音结束后推进。

回执更新同一条助手历史，后续聊天可参考最近6个操作结果；pending、accepted、failed和cancelled的台词不作为成功证据，长期记忆整理也不使用未确认的操作台词作为助手上下文。操作回执最多保留一天，五分钟内可提交；重复相同结果幂等，冲突的迟到终态会拒绝。清除角色会话会删除这些记录，临时交流角色不持久保存操作记录。

## 对话与朗读交接

读书期间，普通聊天不停止整本阅读。回答生成后排入已有语音队列，等当前原文段落自然结束再回应，然后由阅读器按原条件继续；书签只推进已播完的段落。明确的暂停/换书指令仍按用户要求处理。

聊天表情在该条语音真正开始时触发，不在文本刚返回或音频尚未准备好时先表演；关闭语音时按文字回应触发表情。语音结束、失败或取消会释放表演状态。用户手动设置身体和表情后，较早的自动回应不会立刻覆盖。

## 验证范围

自动测试覆盖主要操作互斥、休息和阅读状态保留、显式指令、音乐音源确认、旧操作取消、回执角色隔离/会话清除/幂等、失败历史修正、记忆过滤，以及读书段落后的问答排队与手动表演优先级。浏览器当前不可用，尚未完成真实媒体设备、舞台动画和多轮直播的端到端验收。直播沿用现有FIFO、手动暂停保护与公开记忆链路；本轮新增持久回执主要覆盖普通角色聊天产生的操作计划。
