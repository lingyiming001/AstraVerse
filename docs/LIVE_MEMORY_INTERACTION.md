# 跨场直播记忆与观众投票

入口：创作空间 → 直播 → 绑定当前角色的直播间 →「观众投票」「这个角色的直播记忆」。两个工具默认折叠。所有新增数据仅在本地保存，没有调用外部总结服务。

## 公开场次记录

启动互动创建角色绑定的场次，正常暂停/服务关闭时结算。换绑定会结束旧角色场次；新绑定之后需重新启动互动，才能创建新场次记录。已通过输出检查、提交给本地直播事件出口的角色发言写入独立SQLite档案，不代表平台送达或观众已经听见。

每场最多记录2000条事件、每条最多1200字；达到上限后不再追加，现有记录保留。普通回应/知识、虚构回忆/梦境与程序投票结果分别标记，不写入私人对话记忆，不把主播说法认定为外界事实。不会专门保存原始观众弹幕、昵称名单或个人偏好档案；公开主播发言本身仍可能引用昵称或观众原话。

本轮摘要是可审计的摘录，不是语言模型二次推断：保留最近8条记录与最多4条最近的实际投票结果，去重后标注来源事件ID；界面可查看对应原始事件。下一场仅把该角色最近3份已结算摘要的有限摘录作为参考，提示模型只在相关时自然承接，不能假定当前观众是以前的观众，也不能把虚构经历转为现实经历。

列表最多展示最近20场；原始事件接口按角色与场次双重校验。清空只影响此角色的直播档案，不删其他角色或私聊记忆；正在运行的旧场次也不会在清空后重新写入，重新启动才会建立新场次。

异常退出的未结算场次可查看原始事件，但不会用于跨场次回忆；尚无自动故障结算。场次列表使用数据库UTC时间。尚未实现长期观众身份关联、按话题语义检索、未兑现事项识别或全文阅读进度。

## 弹幕投票节目

运营者填写问题、2–4个不同选项和15–600秒持续时间，发起后由统一直播出口播报。观众发送数字1–4参与，每个昵称保留最后一次有效选择；需先通过已开启的弹幕管理规则，故限频会影响快速改票。昵称不是平台验证身份，统计只称“昵称参与数”，不承诺真实人数。

投票期间暂停冷场自说，其他弹幕仍可正常排队回应；数字投票本身不调用模型。到达截止后不再收票，调度循环或下一条弹幕触发结算与播报；网络/推理繁忙时结果播报可能延迟，但不会延长实际收票期限。也可手动提前结束。并列明确列出并列选项，没有票则不产生胜出选项，不伪造观众或默认投票。结束后的数字不再排成普通聊天。

投票结果由程序统计、独立留档；播报仍经过统一内容检查，休息/到期时可结算但不会强行朗读。暂停互动会取消未完成投票，不产生胜出结果。投票与票箱是内存状态，崩溃不自动恢复。

这是桥接弹幕上的关键词投票，不是平台原生投票。直播间发回平台开关继续决定是否投递公告；关闭时只有本地事件/字幕/语音。结果不自动切换场景或播放资源，也不涉及付费投注。后续可在可靠资源绑定与执行回执完成后，增加“投票结果→节目动作”，并继续保留角色拒绝不合适行为的边界。
