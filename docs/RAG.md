# 资料库与角色记忆检索

聊天与直播在生成回答前检索实际资料。回答下方的“参考资料”可查看本轮送入模型的片段及章节、页码或字幕时间；这些是参考证据，并不表示回答中的每一句话都已经过事实核验。

## 使用

1. 在书籍库批量导入 TXT、Markdown、EPUB、文字 PDF、DOCX 或 SRT/VTT。已有整本书正文会自动建立索引；浏览器中既有文件在刷新页面后同步。无需重复上传到另一个知识库。
2. 展开书籍库的“资料检索”，查看每份文件的状态，必要时重建。默认启用全文检索，可直接问某段情节、术语或资料里的问题。
3. 需要同义表达召回时，在设置 → 平台模型添加支持 OpenAI 兼容 `/embeddings` 的模型，为它勾选“向量检索”能力，再把该能力路由指向此模型。例如兼容服务中的 `text-embedding-v4`；使用供应商提供的实际模型名称与 API 地址。可在模型测试中测试向量连接。
4. 回到资料检索，打开“语义检索”。索引后台串行建立，全文检索保持可用。只有实际存在的向量模型路由才能开启。开启后正文片段和来源明确的角色记忆会发往该模型供应商；默认不开启、不自动新增或修改供应商凭据。

扫描 PDF 需要先 OCR；加密 PDF 不支持。当前不自动转写音乐或解析视频画面。TXT/MD/EPUB 继续支持整本朗读、原有书签与连续阅读；PDF/DOCX/字幕当前用于检索。

## 实现

- SQLite FTS5：中文二/三字词组与英文词的 BM25 检索，约 900 字一段、100 字重叠，保留章节、页码或时间位置。标题也参与匹配。
- Qdrant 本地持久化：向量查询预过滤当前有权访问的文档和有效版本。使用模型/服务指纹及维度隔离集合，防止不同向量空间混用；每批最多 10 段。暂不自动切换后备模型，以免混用向量空间。
- 两路结果用 RRF 合并，最多 6 段（配置接口可调 1–10）。短追问仅参考此前用户问题扩展检索，不采用助手编造的书名作为依据。未匹配到证据时明确不允许假装读过原文。
- 角色资料只对所属角色开放，直播只取标记公开的资料；私有资源始终不进入直播，即使直播角色有私下访问权限。选中的私聊记忆与公开直播记忆分别索引，保留现有兴趣筛选和清除入口。
- 检索网络等待后、回答生成后重查权限和文档版本。替换、删除及清除记忆会删除全文片段、取消旧索引任务并清理向量；即使物理向量清理失败，SQL 版本过滤也阻止召回。来源展开时再次校验权限。失败索引不会在每轮对话中无限重试，可手动重建。
- 音乐存在性、阅读进度、身体动作及播放操作仍依靠真实目录和执行回执，不由检索结果授权，也不因为检索到歌曲名称就声称播放成功。

## 存储与部署

索引与现有 `agent-memory.sqlite3` 共用 SQLite，向量位于同目录 `agent-memory.rag-vectors/`。依赖已加入 Python 项目与锁文件，无须另启向量服务器。备份时先停止 API，再一起备份 SQLite、向量目录、角色配置与浏览器原文件；不要只复制其中一个数据库。

当前 Qdrant local 适合本机单 API worker；不要让多个进程同时打开同一路径。需要多用户或多 worker 时，可在 `modules/rag/vectors.py` 适配远程 Qdrant，并增加工作区/用户隔离及队列服务。这一版不包含跨用户服务化部署、OCR、重排模型或大规模检索效果基准。

主要接口：`/api/rag/settings`、`/status`、`/search`、`/reindex`、`/documents/{resource_id}/file`、`/chunks/{chunk_id}`。当前沿用本机应用访问边界，并非面向公网的鉴权接口。
